# 役次元·数字炸弹

基于 Flutter 的数字炸弹游戏，支持 Android 和 iOS。玩家在限定范围内轮流猜隐藏数字；游戏会提示数字偏大或偏小，并逐步缩小可猜范围。游戏需要连接 YYC-DJ 蓝牙电击器后才能开始。

当前源码版本：`1.0.0+41`，以 `pubspec.yaml` 中的 `version` 为准。

## 功能

- 单人挑战与多人轮流猜测；多人模式由默认名称为 `Master` 的第一位玩家设置炸弹数字。
- 支持炸弹模式、猜错惩罚和淘汰模式；淘汰模式仅供多人游戏使用。
- 可同时连接多个电击器，为不同玩家分配设备的 A/B 通道；设备列表显示广播名称和根据信号强度估算的距离。
- 多人模式需所有玩家确认就绪，猜测者还需连接并分配各自的设备通道，才能设置炸弹并开始游戏。
- 支持中文、英语、法语、德语、荷兰语、西班牙语、韩语、日语、意大利语和俄语；语言选择会保存，切换时不重置游戏。
- 默认使用街机动效：倒计时紧迫提示、猜错短抖动、命中爆发音效与震动；系统开启减少动态效果时关闭抖动和闪动。
- 支持音效、震动开关和手机、平板布局。

## 玩法

1. 选择单人或多人模式，设置数字范围和规则。范围必须在 `0～9999` 内，最小值小于最大值；默认范围为 `1～100`。
2. 扫描并连接 YYC-DJ 设备。单人模式选择一个设备通道；多人模式为每位猜测者分配不同的“设备 + A/B 通道”组合，由所有玩家确认就绪。多人模式至少需要 2 位猜测者，最多 7 位。
3. 单人模式由系统随机生成炸弹数字。多人模式由 `Master` 输入并锁定炸弹数字，再交给猜测者轮流输入。
4. 每回合有 5 秒输入时间。猜错后，提示炸弹数字更大或更小，已猜过的数字会从可猜范围中移除。超时算一次失误，但不会缩小范围。设备输出或断开时倒计时暂停。
5. 猜中炸弹数字，或淘汰模式只剩一位猜测者时，本局结束并显示结果。

### 惩罚规则

- **炸弹模式**：猜中炸弹算失败，向该玩家通道输出 10 秒；普通猜错和超时不输出。
- **猜错惩罚**：猜错或超时不立即输出，但会使最终失败时的强度增加 5，最高 180；猜中炸弹时向该玩家通道输出 10 秒。
- **淘汰模式**：累计 3 次失误出局，出局当下向该玩家通道输出 10 秒；猜中炸弹也算失败并输出 10 秒。未出局的玩家不受罚；只剩一位猜测者时结束。

初始强度由设置页滑块决定，默认是 `0`；强度为 `0` 时不会向设备输出强度。只有“猜错惩罚”模式会因失误累加强度，其他模式使用固定初始强度。惩罚只发送到失败玩家分配的设备通道。界面提供紧急停止按钮；使用前请确认设备和接线状态。

设备距离由蓝牙信号强度估算，只能作为大致参考，不代表实测距离。设备广播名称保持原样，不随界面语言翻译。

## 开发与构建

准备 Flutter SDK（当前开发环境为 Flutter `3.47.5`、Dart `3.13.4`）、Android SDK 和 JDK 17。首次构建先检查环境并获取依赖：

```bash
flutter doctor -v
flutter pub get
flutter analyze --no-fatal-infos
flutter test
```

构建 Android APK：

```bash
flutter build apk --release
```

街机音效文件已包含在源码中；修改音效后运行 `python scripts/generate_arcade_sfx.py` 重新生成。

产物位于 `build/app/outputs/flutter-apk/app-release.apk`。已开启 USB 调试的 Android 设备可通过以下命令安装：

```bash
adb install -r build/app/outputs/flutter-apk/app-release.apk
```

当前 `release` 构建仍使用 Android Debug 签名，仅用于本地安装和测试。正式分发前，需要在 `android/app/build.gradle.kts` 配置发布签名。不要手动解包再压缩 APK，以免破坏安装所需的文件对齐。

若 Windows 上的 Java 报 `Unable to establish loopback connection`，可将下方路径换成已存在的短路径，在当前 PowerShell 会话中重试：

```powershell
$env:JAVA_TOOL_OPTIONS='-Djdk.net.unixdomain.tmpdir=C:/gradle-tmp/tmp'
flutter build apk --release
```

iOS 需在 macOS 和 Xcode 环境中配置签名，再运行 `flutter build ipa --release`。本仓库不包含 APK、iOS 签名文件或本机配置；这些文件需要在各自的构建环境中生成或配置。
